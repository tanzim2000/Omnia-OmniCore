Default UI: every element

Everything defined in core/ui-theme.js, the stylesheet behind OmniCore's own pages (Settings, welcome, wizard, input faces). Samples below are live: hover, focus and click them. Built from the real file at version 1.19.4; flip Dark / Light above to see both palettes.

Foundations

What every other element is built from.

Global variables

:root

Three layout variables set on every page, besides the colours above. They are the only knobs the Settings page changes.

--fontThe font stack. System font until a Google font is installed, then "Name", system-ui….
--font-sizeBase size in px (default 16). Almost everything is in em, so changing it scales the whole UI.
--radius0.75em. Corner radius of segments, lists, tabs, glass buttons.
--segment-blurnone by default. Set to e.g. blur(0.75em) to turn every segment into frosted glass.
:root {
  --font: system-ui, …;
  --font-size: 16px;
  --radius: 0.75em;
  --segment-blur: none;
}

Note. If --segment-blur is turned on, a blurred box becomes the frame for any position: fixed child, so pop-ups (.modal-backdrop) must sit outside every segment.

Page body and ambient background

body

Page background colour with two very faint radial blobs (--ambient-a, --ambient-b) fixed behind the content. They exist only so backdrop-filter blur has something to blur. Margin 0, text in --fg, font from --font.

The soft glow you can see behind this whole catalogue page is it.

body { background: var(--bg); color: var(--fg); font-family: var(--font); … }

Note. Automatic rule: body:has(> .floating.top-left) gets extra top padding, and body:has(> .floating.bottom-right) extra bottom padding, so the back button never sits on top of content.

Text styles

h1 · .lede · label · .help · .hint · .empty · .muted

The few text styles the Default UI has. h1 is the page title (light weight). .lede is the line under it. label sits above a field. .help is the small note under a field, .hint the small block-level grey text, .empty the “nothing here” message, .muted any grey text.

Page title

A lede: one quiet line explaining the page.

.help — small note under the field.
.hint — small grey text, its own line.

.empty — nothing to show yet.

.muted — any text in the quiet colour.

<h1>Page title</h1>
<p class="lede">One quiet line.</p>
<div class="field">
  <label>Label</label>
  <input type="text">
  <div class="help">Small note.</div>
</div>

Buttons

Everything clickable that looks like a button.

Glass button

.glass

The primary button. Translucent fill, bevelled edge, a light sheen over the top half, and a white halo on hover/keyboard focus. Shrinks slightly when pressed. Works on <button> or <a>.

<button class="glass">Save</button>
<button class="glass" disabled>Saving…</button>

Note. :disabled is faded, no glow, no press. Use it whenever a click would do nothing (Update now without Docker, Save while saving).

Coloured glossy buttons

.btn-glossy .btn-glossy-green / .btn-glossy-neutral

For the few moments that should stand out: green = the safe or finished choice (“Installed”, “Go back”), grey = the second choice. Smaller and squarer than .glass. Always combine .btn-glossy with a colour class. Green reads its own --success-button-* variables, so it can be calmer than the status green.

<button class="btn-glossy btn-glossy-green">Installed</button>
<button class="btn-glossy btn-glossy-neutral">Cancel</button>

Note. Dark mode: glossy with a bevel. Light mode: flat, white label, no shadow.

Dock (capsule button)

.dock > button (+ .danger)

One continuous capsule holding two or more actions separated by thin rules, e.g. the wizard's Back | Next and a module's Save | Remove. It sits in the page flow (not floating). Same glow and sheen as .glass on each section. Width is fixed (26em portrait, 30em landscape) however many sections it holds. Nothing in it is ever marked “active”.

<div class="dock">
  <button type="button">Save</button>
  <button type="button" class="danger">Remove</button>
</div>

Note. .danger gives a red label and a red halo on hover — a warning colour, not the safeguard: the action should still ask first. Not overflow:hidden on purpose (it would clip the glow).

Dock with a disabled section

.dock button:disabled

A section that can't be pressed right now (e.g. Back on step 1, Save while saving): faded, no glow.

<div class="dock">
  <button type="button" disabled>Back</button>
  <button type="button">Next</button>
</div>

Floating round button

.floating + .bottom-right / .top-left / .top-right

A flat (not glossy) round button fixed to a corner, flashing on tap rather than glowing. Used as the Back button (←). Corner is a user setting; bottom-left is never offered because the welcome face's auto-advance timer lives there.

top-left and bottom-right shown
<button class="floating bottom-right" aria-label="Back"
  onclick="location.href='/'">&#8592;</button>

/* or let the helper write it: */
backButton("/")

Note. The demo is fenced into this box; on a real page they are fixed to the screen corners. In code use backButton(href), which picks the corner from the saved setting.

Light / dark switch

.floating.top-right.mode-switch

A smaller round floating button, top-right, only on the sign-in/setup page: everywhere else the choice lives in Settings → Appearance. Shows where it would take you: a sun on a dark page, a moon on a light one.

modeSwitch()   // helper that writes the button, both icons included
// the stylesheet shows the right icon; MODE_SWITCH_SCRIPT wires the click

Note. Click it in this catalogue's top bar instead — that one is wired up (it toggles this page only).

Show / Hide button

.password-toggle (inside .password-field)

Borderless text button inside the right end of a password box. Swaps the box between password and plain text so a typo can be checked. Nothing leaves the page because of it.

passwordField('<input type="password" id="pw" autocomplete="current-password">')

Note. Wired by PASSWORD_TOGGLE_SCRIPT, one listener for the whole page. It works in this demo.

Modal close button

.modal-close

The ✕ in a pop-up's header. Deliberately not a glass button: closing is the least important thing on the panel and shouldn't pull the eye before the content.

<button class="modal-close" aria-label="Close">&#10005;</button>

Containers and lists

Boxes and scrolling lists that pages are built from.

Segment

.segment

THE box. Every page is built from these: each tile in Settings, the wizard's halves, a face in the welcome list, a marketplace listing. Replaced the old .card and the two .tile rules. Nothing happens on hover.

A plain segment — a container.
<div class="segment">…</div>

Clickable segment

.segment.clickable

A segment where the whole box is a link or button. Dark mode: glows on hover. Light mode: lifts slightly (a glow disappears on a pale page). Hover the box to see it in the current mode.

Hover me: a clickable segment.
<a class="segment clickable" href="/faces/001">…</a>

Scrollable list

.list

A column that scrolls inside itself (max 60vh) so the page doesn't. Children don't shrink, so long rows scroll instead of being squashed. Slim custom scrollbar.

Single-line row

.font-row

A clickable segment used as a one-line row inside a .list: name on the left, a secondary label pinned right (.hint). Used by the font picker; good for any long list that reads better at one line per entry.

.list-fill

Like .list but grows to the height its parent gives it instead of capping at 60vh, scrolling only when it truly runs out. For a segment stretched to fill the screen. The parent must be a flex column with a height.

Toolbar

.toolbar (+ .toolbar-note)

One row of controls for a list: a search box that takes the leftover room, a tabs switch, a quiet count. Wraps on narrow screens rather than squeezing the search. Layout only: put it on a .segment to get the box.

9 items
<div class="segment toolbar">
  <input type="text" placeholder="Search">
  <div class="tabs">…</div>
  <span class="toolbar-note">9 items</span>
</div>

Modal (pop-up)

.modal-backdrop > .modal (.modal-head, h2, .modal-close)

A centred panel over a dimmed, blurred backdrop, for controls needing more room than their segment can give (font picker results, location search). The backdrop covers the whole screen (z-index 100); add the hidden attribute to hide it. Max 26em wide, 80vh tall.

Choose a font

Adaminaserif
<div class="modal-backdrop" hidden>
  <div class="modal">
    <div class="modal-head">
      <h2>Title</h2>
      <button class="modal-close">&#10005;</button>
    </div>
    …
  </div>
</div>

Note. Must sit outside every .segment (see --segment-blur above). Fenced into this box for the demo; normally fixed over the whole screen.

Choices and switches

Ways of picking.

Tabs (segmented choice)

.tabs > .tab-btn (+ .active)

A pill of named options where one is active. Use when options are labelled things (Dark / Light / Device, Modules / Themes, corner names), not a plain on/off. Each option usually reveals different content below.

<div class="tabs">
  <button class="tab-btn active">Dark</button>
  <button class="tab-btn">Light</button>
</div>

Note. Clicking works in this demo. In the real UI the page's own script moves .active.

Toggle switch

.switch (.switch-track, .switch-knob)

A sliding on/off knob for a plain yes/no preference with nothing else attached. Green when on. Different from tabs on purpose: switch = binary, tabs = labelled choice.

  
<label class="switch">
  <input type="checkbox" checked>
  <span class="switch-track"><span class="switch-knob"></span></span>
  <span>Enabled</span>
</label>

Number stepper

.stepper

Minus button, number, plus button, for a small bounded number tapped through step by step (text size). Uses two small .glass buttons; the browser's own spinner is hidden because the buttons are the up/down control. Not a slider: a slider is for a continuous range.

<div class="stepper">
  <button class="glass">&minus;</button>
  <input type="number" value="16">
  <button class="glass">+</button>
</div>

Widget type picker

.widget-picker > .widget-choice (+ .active)

A grid of one button per widget type a module offers (Month View, Agenda View…), at the top of an instance's settings. Shaped like the option rows so it reads as part of the form. Only shown when a module actually offers a choice.

<div class="widget-picker">
  <button class="widget-choice active">
    <strong>Month View</strong><small>…</small>
  </button>
</div>

Note. .widget-off hides a setting that belongs to a widget type other than the one picked (display:none !important, separate from showWhen).

Option row

.option

A bordered row holding a checkbox or radio and its label; the whole row is the click target. A list of these is a pick-one or pick-many.

<label class="option"><input type="radio" name="o"> Automatic</label>

Form fields

Inputs and the pieces around them.

Field

.field

A label, a control and an optional .help note, with 20px below. The standard unit of every form.

Shown in the browser tab.
<div class="field">
  <label>Server name</label>
  <input type="text">
  <div class="help">Note.</div>
</div>

Text, URL, number, password, select

input[type=text|url|number|password], select

All share one look: full width, glass fill, thin border, rounded. The dropdown's popup list (option) is forced to the page colours, otherwise it is white-on-white in dark mode.

<input type="text">
<input type="url">
<input type="number">
<input type="password">
<select><option>…</option></select>

Password field

.password-field

Wraps a password input and puts the Show / Hide button inside its right end. Room is kept on the right so typed text never runs under the button.

passwordField('<input type="password" id="pw">')

Checkbox and colour picker

input[type=checkbox], input[type=color]

Checkbox is a plain 18px box (switch is the nicer on/off). The colour input is full width, 46px tall, glass fill.

<input type="checkbox">
<input type="color" value="#4a90e2">

Search row and results

.search-row · .result

A text box with a button beside it (box takes the room), and under it a stack of full-width result buttons (location search, etc.).

<div class="search-row">
  <input type="text"><button class="glass">Search</button>
</div>
<button class="result">Result</button>

Status and labels

Small pieces that say something.

Status message

.status (+ .good / .bad)

One line of feedback under an action (“Saved”, “Couldn't save”). Green for .good, red for .bad. :empty collapses it completely so it takes no room until there is something to say.

Saved.

Could not save: the port is taken.

(an empty .status takes no space)
<p class="status" id="status"></p>
status.textContent = "Saved."; status.className = "status good";

Badge

.badge

A small outlined label beside a word, e.g. “dev” after a development build's version. It says something about its neighbour: it isn't a button and doesn't react.

1.19.4 dev
1.19.4 <span class="badge">dev</span>

versionHtml()   // does this for you

Helpers & scripts

Not visible elements, but exported by ui-theme.js for pages to use.

uiStyles({forceMode})Returns the whole stylesheet as text. Pages drop it in a <style> tag. forceMode 'light'/'dark' wins; otherwise this browser's cookie; otherwise both palettes and the device decides.
backButton(href)Markup for the floating Back button, in the corner chosen in Settings. Returns nothing when href is empty (root pages: welcome, input faces, wizard).
modeSwitch()Markup for the sign-in page's sun/moon round button (both icons included).
passwordField(inputHtml)Wraps a password input with the Show / Hide button.
versionHtml()The version as a page shows it: “1.19.4”, plus a dev badge on a development build.
fontStack(settings) / fontFace(settings)The CSS font-family stack, and the @font-face rule pointing at /ui-font.woff2?v=… for a downloaded font (nothing for the system font).
UI_MODE_SCRIPTScript providing setUiMode(mode): sets or clears the omnicore_ui_mode cookie and reloads. Used by the Appearance tile and the sign-in switch.
MODE_SWITCH_SCRIPTClick handler for the sign-in switch: flips to whichever mode isn't showing.
PASSWORD_TOGGLE_SCRIPTOne page-wide listener that powers every Show / Hide button.
rememberUiMode / uiModeFromRequest / currentUiModeServer side: read the cookie (only exactly 'light' or 'dark' counts) and make it available to uiStyles() for the current request.
PALETTES · SYSTEM_FONT · UI_MODE_COOKIEThe colour tables, the system font stack, and the cookie name (omnicore_ui_mode).
